# 코테 연습실 · Cote Practice Lab

Java 코딩테스트를 실제로 풀면서 코드 변경·실행·제출·힌트·앱 화면·마이크를 기록하고, 같은 시간축으로 되돌려 보며 Codex와 복기하는 개인용 로컬 웹앱입니다. [합의된 설계](SPEC.md)를 바탕으로 기존 풀이 기록장을 다시 구성했습니다.

## 지금 실행하기

필요한 도구와 모델을 설치한 뒤 프로젝트 폴더에서 실행합니다.

```bash
cd cote-coach
./run.sh
```

실행 시 `Java 편집 지원 준비 중…`이 끝나고 주소가 출력되면 **http://localhost:8766** 을 Chrome 또는 Edge에서 엽니다. 다른 포트는 `./run.sh --port 8770`으로 지정합니다. 서버 종료는 `Ctrl+C`입니다. 화면 녹화는 현재 앱 탭을 선택해야 하며 마이크 권한도 필요합니다. 모바일은 기록 확인 위주로 사용하고 실제 풀이에는 데스크톱 브라우저를 권장합니다.

처음 설치할 때는 Python 3.11 이상, Node.js, npm, Docker, curl, tar와 Codex CLI를 준비하고 다음을 실행합니다.

```bash
./setup.sh
codex login
./run.sh
```

설치 시 Docker 이미지, Eclipse Java 언어 서버, 한국어를 지원하는 Whisper small 모델을 다운로드합니다. Java 실행은 Docker의 Java 21, 편집 기능은 별도 JDK 25로 실행하는 JDT LS와 Java 21 프로젝트 설정을 사용합니다. 호스트의 기본 Java 설정을 바꾸지 않습니다.

## 연습하는 방법

1. **연습 시작**에서 문제를 고르고 한 문제/모의 코테, 실전/훈련, 제한 시간, 자료 사용 범위를 선택합니다.
2. 현재 Codex 계정이 제공하는 **모델과 추론 수준**을 선택합니다. 나중에 복기할 때 선택해도 기록 연습은 가능합니다.
3. **녹화 준비 후 시작**을 누르고 브라우저의 **현재 코테 연습실 탭**과 마이크를 허용합니다. 다른 탭·창·화면은 받지 않습니다.
4. Java 코드를 작성하고 실행·제출합니다. 접근법을 정하거나 막혔거나 접근법을 바꿀 때 생각을 짧게 말합니다. 텍스트 메모는 오른쪽 생각 기록 영역에 바로 남길 수 있습니다. 훈련 모드의 **풀이 코치**에서는 팝업 없이 힌트를 받습니다. 질문을 비워도 현재 코드·실행 결과로 요청할 수 있고, **말로 질문 → 말 마침 · 힌트 받기**는 인식 후 바로 요청합니다. 모델은 시작 설정을 이어 쓰며 코치 상단에서 바꿀 수 있습니다. 클래스 본문에서는 접근 제한자 키워드를 먼저 제안하고 `psvm`, `psf`, `prsf` 등의 코드 틀을 지원합니다. 자동완성 선택은 Tab, Enter는 줄바꿈입니다.
5. 연습 종료 후 **음성 전사**로 로컬에서 음성을 텍스트로 변환합니다. 인식 오류는 수정해서 저장할 수 있습니다.
6. 시간축에서 그때의 코드·영상·발언·최근 실행을 확인합니다. 필요한 영상 장면은 최대 4개를 직접 골라 Codex 분석에 첨부할 수 있습니다.
7. **분석 시작** → 코치 질문에 텍스트/음성 답변 → **최종 보고서** 순서로 복기합니다. 음성 답변은 인식 결과를 확인하고 답변 보내기를 누릅니다.
8. 보고서의 근거 시각을 눌러 확인하고, 다음 연습 추천에 반영합니다.

## 모드와 채점 규칙

| 기능 | 실전 | 훈련 |
| --- | --- | --- |
| 편집 지원 | 문법 색상, 들여쓰기, 괄호 닫기 | 기본 지원 + Java 타입 분석 자동완성, 자동 import, 인자/코드 틀, 문서·매개변수 안내, 오류 표시 |
| 코치 개입 | 풀이 중 없음 | 요청할 때 작은 힌트 |
| 시간 종료 | 서버가 마감 코드를 고정해 자동 제출, 편집 종료 | 마감 코드 별도 보존, 이후 풀이는 추가 시간으로 구분 |
| 자료 사용 | 금지 / Java 공식 문서 / 자유 검색을 시작 전에 선택 | 선택한 조건을 기록 |

화면 녹화는 앱 탭만 대상으로 합니다. 외부 자료 사용 조건은 자율 연습 규칙이며 다른 앱·탭의 내용을 감시하거나 시스템 전체 검색을 차단하지 않습니다. 포커스 이탈을 검색 또는 부정행위로 단정하지 않습니다.

채점은 **앱에 준비된 테스트 기준**입니다. 프로그래머스의 비공개 채점 데이터나 공식 통과 판정과 동일하지 않습니다. 실행 시간 수치에는 Docker 시작과 컴파일이 포함되어 있으므로 알고리즘의 정밀 벤치마크가 아닙니다.

Java 코드는 네트워크 없이, 호스트 소스 폴더를 읽기 전용으로 연결한 Docker 컨테이너에서 실행합니다. 비특권 사용자, 512MB 컨테이너 메모리, 192MB Java 힙, 1 CPU, 프로세스 수 제한, 컴파일 포함 20초 제한, 128KB 출력 제한을 적용합니다. Docker가 준비되지 않으면 호스트 실행으로 우회하지 않습니다.

테스트 입력은 Java 소스에 넣지 않고 표준 입력의 이진 스트림으로 전달합니다. 채점 하네스는 문제 형식에만 의존하는 고정 크기 코드이며, 모든 입력을 읽은 뒤에 풀이를 호출하므로 풀이 코드가 다음 테스트 입력을 읽을 수 없습니다. 시간 제한은 세 가지입니다.

- 전체: 컨테이너 시작·컴파일·모든 테스트를 합쳐 20초.
- 테스트당: 각 호출 3초(JVM 안에서 측정, 컴파일 제외).
- 대입력 성능 테스트: 제한 조건 최대 크기 입력, 호출당 1초, 그리고 한 번의 제출 안 모든 성능 테스트 합계 2초(JVM 안에서 측정, 컴파일·입력 읽기 제외).

합계 예산을 두는 이유: JIT가 최적화한 O(n²) 두 수의 합 풀이는 빠른 컴퓨터에서 n=100,000 한 건에 약 0.6초라서, 한 건의 시간만으로는 O(n)과 안정적으로 구분할 수 없습니다. 두 수의 합에는 최대 크기 성능 테스트가 8건 있어 O(n²)는 합계 약 4.5초 이상이 필요하고 2초 예산에서 실패합니다. 선형 풀이는 한 건에 수십 ms 이하라 합계 예산 대비 10배 정도 여유가 있습니다. 매우 느린 컴퓨터에서는 효율적인 풀이도 시간 초과가 날 수 있고, 반복문이 벡터화되는 단순 풀이(예: 연속 구간 합의 O(nk))는 일부 컴퓨터에서 통과할 수 있습니다. 이 앱의 채점은 실제 온라인 저지의 판정과 같지 않습니다.

시간 초과가 나면 그 테스트를 `시간 초과`(테스트당 제한 또는 성능 합계 제한)로 표시하고 이후 테스트는 실행하지 않습니다. 대입력 테스트는 고정 seed 생성 규칙(`coach/problems.py`의 `GENERATORS`)으로 채점할 때만 만들며, 세션 기록·화면·분석 자료에는 입력이 들어가지 않습니다. Docker 실행 실패, 컴파일 단계 시간 초과, 실행 환경 비정상 종료처럼 풀이와 무관한 장애는 결과 `status: "error"`와 `grader_error`로 구분하고 화면에 **채점기 오류**로 표시합니다.

## 문제 라이브러리

직접 작성한 Lv.1~2 문제 6개와 예제/추가 테스트가 포함되어 있습니다. 대입력 제약이 있는 문제(물품, 두 수의 합, 괄호, 연속 구간, 계단)에는 최대 크기 비공개 테스트가 있어, 작은 예제만 통과하는 비효율 풀이는 제출에서 실패합니다. 추천은 기존 복기에서 나온 유형과 최근 풀이·복습 간격을 활용하는 규칙 기반 추천입니다. 문제은행 전체를 수집하거나 외부 사이트를 자동 크롤링하지 않습니다.

**문제 가져오기** 화면에서 이름·설명·제한 조건·Java 메서드 형식·시작 코드·예제/추가 테스트를 입력할 수 있습니다. 입력 인자는 JSON 배열 표기를 사용합니다. 클래스명은 `Solution`이며 매개변수와 반환형이 등록한 형식과 같아야 합니다. 내부 문제 형식 예시:

```json
{
  "title": "배열 합 연습",
  "level": 1,
  "tags": ["배열·문자열"],
  "url": "",
  "description": "numbers의 합을 반환하세요. 길이는 0~100입니다.",
  "method": "solution",
  "returns": "int",
  "params": [{"type": "int[]", "name": "numbers"}],
  "starter": "class Solution { public int solution(int[] numbers) { return 0; } }",
  "tests": [
    {"args": [[1, 2, 3]], "expected": 6, "public": true},
    {"args": [[]], "expected": 0, "public": false}
  ]
}
```

생성 규칙 테스트도 쓸 수 있습니다. 예: `{"generate": {"name": "pair", "shape": "zeros", "n": 100000, "seed": 0}, "time_limit_ms": 1000, "performance": true}`. `performance: true`인 테스트는 성능 합계 예산을 함께 씁니다. 생성 테스트는 항상 비공개이며 기대값은 규칙이 함께 만듭니다. 생성 결과가 문제의 매개변수·반환형과 맞지 않으면 등록을 거부합니다.

지원 타입: `int`, `long`, `double`, `boolean`, `String`, `int[]`, `long[]`, `String[]`, `int[][]`, `boolean[]`. 임의의 Java 객체·리스트 시그니처는 아직 지원하지 않습니다. `double` 채점은 현재 정확한 값 비교이며 허용 오차 채점은 제공하지 않습니다. 사용자 문제의 기대값이 맞는지 확인해야 합니다.

## 다시 풀기 예약

완료한 연습의 문제별 복기 화면에서 실패 이유와 일정 기준 시간대를 확인하고 **1·3·7일 뒤 예약**을 저장할 수 있습니다. 시간 내 마지막 전체 제출이 실패했거나 시간 내 제출이 없는 문제를 직접 등록하며, 채점 중·채점 오류·판정 불명은 오답으로 등록하지 않습니다. 추가 시간에 통과해도 시간 내 결과는 따로 남습니다.

등록할 때의 현지 날짜를 기준으로 세 날짜를 고정합니다. 홈의 **오늘 다시 풀 문제**에서 오늘과 밀린 회차를 확인하고 앞선 미완료 회차부터 시작합니다. 통과해도 남은 일정은 유지하며 자동 알림은 없습니다.

재도전은 저장된 원본 문제 정의와 starter로 새 세션을 만듭니다. 준비·풀이 화면과 새 힌트 입력에서 이전 코드·해설·태그·등록 이유를 숨기며, 기존 기록은 그대로 보존합니다. 완료 후 원본과 현재 시도의 문제별 경과 시간, 시간 내·추가 시간 제출 결과, 연습 조건과 힌트 사용을 비교합니다. 채점이 끝나기 전에는 비교를 기다리고, 늦게 복구된 기록에 따라 비교값이 갱신될 수 있습니다. 탭을 닫은 시간도 경과 시간에 포함됩니다.

문제 제목·본문·starter에 포함된 풀이 단서는 삭제하지 않으며, 사용자가 별도 탭에서 직접 과거 기록을 여는 행위까지 막지는 않습니다. 예약은 SQLite 전체 기록 백업에 함께 포함됩니다.

## Codex와 사용량

- 앱은 Codex App Server를 통해 기존 **ChatGPT 로그인**을 사용합니다. 별도 OpenAI API 키를 요구하거나 자동으로 API 요금제로 전환하지 않습니다.
- 모델 목록과 지원 추론 수준은 실제 계정에서 가져옵니다. 선택 불가 조합은 오류로 알리고 임의 대체하지 않습니다. 서비스 측 모델 변경 알림을 받으면 그 결과를 선택 모델의 정상 결과로 저장하지 않습니다.
- 풀이 기록·미디어 수집은 Codex 호출을 하지 않습니다. 힌트·분석·복기 답변·최종 보고서 요청에서 사용량이 발생합니다.
- 하나의 연습은 같은 Codex 스레드를 이어서 사용합니다. 기록을 저장한 컴퓨터와 별개로 Codex 분석에 필요한 자료는 OpenAI 서비스에서 처리됩니다.
- 입력은 문제, 실행/제출 코드, 최종 코드, 시간순 사건, 음성 전사문, 과거 보고서 요약과 직접 첨부한 영상 장면입니다. 전체 영상 파일을 자동으로 해석했다고 주장하지 않습니다.
- 사용량 절약을 위해 편집 활동은 분석 입력에서 15초 단위로 집계합니다. 각 코드 변경과 원본 미디어는 로컬에 남고 재생할 수 있습니다. 매우 큰 분석 자료는 범위 제한을 표시하거나 분석을 거절하며 원본은 지우지 않습니다.
- 실제 소모량은 모델, 추론, 기록의 양, 대화 횟수 등에 따라 달라집니다. 계정이 제공하는 토큰/한도 정보만 표시하며 이 대화창과 정확히 같은 사용량은 보장하지 않습니다.
- 앱은 새 Codex 턴에서 도구 실행이나 외부 검색 대신 제공한 기록만 분석하도록 지시합니다. 승인 요청이 생기면 자동 허용하지 않습니다.

공식 참고: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [인증](https://learn.chatgpt.com/docs/auth), [사용량](https://learn.chatgpt.com/docs/pricing).

## 녹화와 전사, 중단 복구

- MediaRecorder로 앱 탭 영상과 마이크를 같은 스트림에 기록하며 약 5초 단위로 전송합니다.
- 전송 전에 브라우저 IndexedDB에 저장하고 서버 확인 뒤 해당 조각을 제거합니다. 네트워크 오류 시 임시 데이터는 남습니다. 앱 재접속 또는 **미전송 기록 다시 보내기**로 재전송합니다.
- 원본 조각은 순서와 크기를 기록하며, 누락되면 정상 미디어로 처리하지 않습니다. 재생 시 합치고 종료된 영상은 탐색 가능한 WebM으로 재포장합니다.
- 녹화가 끝나면(정상 종료 또는 공유 중단) 브라우저가 전체 조각 수를 `recording_stop` 이벤트로 남깁니다. 서버는 이 수와 저장된 조각을 대조해 각 녹화를 `complete`(완결), `pending`(연습 중 업로드 대기), `missing`(중간 또는 끝 조각 누락), `recording`(연습 중, 종료 전), `unconfirmed`(종료 확인 없음: 비정상 종료 또는 이전 기록)로 표시합니다. 상태는 매번 다시 계산하므로 늦게 도착한 조각이나 종료 이벤트로 복구됩니다. 누락이 있으면 음성을 분석에 넣지 않고, 종료 확인이 없으면 전사하되 끝부분 누락 가능성을 전사 상태와 복기 화면에 표시합니다.
- 사용자가 공유를 중지하거나 페이지를 새로고침하면 중단 구간을 기록합니다. 재진입 후 **녹화 재연결**을 직접 눌러야 합니다. 녹화 중단 동안의 영상·음성은 복구할 수 없습니다.
- 코드 이벤트의 경과 시간은 브라우저의 단조 증가 시계를 사용합니다. 서버에 확인된 코드가 마감 제출의 기준입니다. 이벤트가 늦게 또는 역순으로 도착해도 (경과 시간, 순번)이 가장 최신인 코드만 현재 코드가 되고, 오래된 이벤트는 원본 기록으로 원래 시각 위치에 남습니다. 같은 시각이면 순번이 큰 편집이 나중이고, 순번이 없는 이전 기록끼리는 도착 순서를 따릅니다. 현재 코드, 복기 재생, 분석 자료의 코드 변화가 모두 이 순서를 씁니다. 진행 중인 연습을 다시 열면 미전송 기록을 먼저 보내고, 보내지 못하면 브라우저에 남은 더 최신 편집으로 편집기를 엽니다. 마감 뒤 복구된 편집 이벤트는 제출 코드를 바꾸지 않고 복구 이력으로 남습니다.
- 녹음은 Whisper small 모델을 CPU/int8로 로컬 전사합니다. 짧은 기술 용어, 잡음, 침묵 등에서 인식이 틀릴 수 있으므로 수정 기능을 제공합니다. 시간 표시는 정밀 계측값이 아닌 전사/녹화에 기반한 위치입니다.
- 영상·녹음은 자동 삭제하지 않습니다. 긴 연습은 상당한 저장 공간을 사용할 수 있습니다. 브라우저 저장 용량이 부족해지면 실패 상태를 표시합니다.

구현 참고: [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder), [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [Eclipse JDT LS](https://github.com/eclipse-jdtls/eclipse.jdt.ls).

## 성장 지표

- 첫 풀이 문제 수, 시간 내 최종 제출 통과 여부, 힌트 없이 독립 해결한 문제 수.
- Java·난이도별 첫 풀이 독립 해결률, 문제를 열어 둔 시간의 중앙값, 평균 힌트 수.
- 세션별 문제 사용 시간, 첫 실행 시점, 실행 횟수, 시간 내/추가시간 결과.
- 보고서의 반복된 관찰과 다음 연습 행동. 원인 가설은 사용자 복기 답변을 통해 확인합니다.

표본이 적거나 문제·자료 사용 조건이 달라진 경우 능력을 단정하지 않습니다. 같은 문제를 외워서 빨리 푸는 것과 새로운 문제를 혼자 해결하는 것을 구분합니다.

Java 편집 기능의 조사 출처, 구현 방식, 검증 범위와 제한은 [Java 편집 지원 문서](docs/java-editor.md)에 정리했습니다.

## 데이터와 백업

```text
data/lab/lab.sqlite3        세션, 사건, 실행, 문제, 코치 대화, 보고서
data/lab/sessions/          녹화 원본 조각, 첨부 장면
runtime/                   JDK, Java 언어 서버, 로컬 음성 모델
```

**연결 · 설정 → 전체 기록 백업**으로 ZIP을 받습니다. 복원은 서버를 종료한 뒤 실행합니다.

```bash
.venv/bin/python restore.py /백업/경로/cote-lab-backup.zip --replace
```

`--replace`는 기존 `data/lab`을 시간 표시가 있는 보관 폴더로 옮긴 뒤 복원합니다. 기존 데이터를 삭제하지 않습니다. 별도 대상은 `--destination /경로/새폴더`로 지정할 수 있습니다. DB 무결성·ZIP 경로를 검사한 후 적용합니다. 테스트 실행 시 `COACH_DATA_DIR`로 별도 데이터 위치를 지정할 수 있습니다.

기존 기록장 데이터 `data/coach.sqlite3`는 유지됩니다. 새 세션으로 자동 변환하지는 않습니다. 비밀 키, 기록, 모델, 빌드 산출물은 Git에서 제외됩니다.

## 검증

```bash
npm run build
.venv/bin/python -m unittest discover -s tests -v

# 별도 터미널: 임시 DB + 코치 응답만 모의 처리하는 테스트 서버
.venv/bin/python tests/lab_fixture.py
# 브라우저 설치가 없다면 npx playwright install chromium
npm run test:browser
.venv/bin/python tests/ide-startup.py
node tests/workspace-ux.cjs
node tests/report-browser.cjs
node tests/recovery-browser.cjs
node tests/java-completion-browser.cjs
node tests/java-editor-matrix.cjs
node tests/completion-protocol.cjs
.venv/bin/python tests/ide-matrix.py
```

`workspace-ux.cjs`는 팝업 없는 힌트, 대기 중 편집, 문제별 응답 분리, 음성 질문 자동 전송, 마이크 재사용, 늦게 도착한 자동완성 응답 무시를 확인합니다. 이 테스트의 음성 인식 결과와 지연 자동완성 응답은 모의 처리합니다.

백엔드 테스트는 마감 코드 고정, 모드별 동작, 중복 이벤트 방지, 문제 가져오기, 미디어 누락 감지, 보고서 저장, 실제 Docker Java 실행/컴파일 오류/호스트 파일 격리 등을 확인합니다. 기존 기록 API 회귀 테스트도 유지합니다.

브라우저 테스트는 화면·마이크 소스를 합성하고 실제 MediaRecorder 업로드·영상 추출·로컬 음성 전사를 사용합니다. Java 실행도 실제 Docker입니다. 코치 응답만 테스트용으로 대체하므로 테스트마다 유료 추론을 반복하지 않습니다. 실제 Codex 연결 및 구조화된 응답은 별도 간단한 연결 검증을 수행했습니다. Chromium의 실제 탭 캡처와 현재 탭 확인도 별도로 검증했습니다(마이크 입력은 테스트 장치). 실제 사람 목소리의 한국어 인식 정확도와 사용자의 마이크 장치는 직접 사용 시 확인해야 합니다.

## 구조

- `client/`: Monaco 편집기, 한국어 UI, 브라우저 녹화와 IndexedDB 전송 대기열
- `coach/`: 세션·채점·미디어·로컬 전사·JDT LS·Codex 연결
- `server.py`: localhost HTTP 서버 및 기존 기록 API
- `tests/`: 데이터/실행/브라우저 검증
- `SPEC.md`: 확정된 요구사항과 설계 근거

개인용 localhost 앱입니다. 로그인·다중 사용자·인터넷 공개 배포는 구현 범위에 포함하지 않았습니다.
