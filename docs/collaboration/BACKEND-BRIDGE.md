# Claude에서 백엔드 Codex에 요청하기

현재 Claude Code가 프런트 작업의 진행을 맡고, 필요한 순간에 이 실행 도구로 별도 Codex를 호출한다. 사용자에게 요청·응답을 복사해 달라고 할 필요는 없다. 상시 감시 프로세스는 없으며 호출 1회가 끝나면 종료한다.

## 1. 요청 작성과 호출

`docs/collaboration/002-claude-request.md`처럼 고유 번호로 작성한다. 목적, 필요한 API 예시, 완료 조건, 현재 수정 중인 프런트 파일을 포함한다. 후속 질문은 이전 요청/응답의 관련 내용을 붙이고 새 번호를 사용한다.

질문·설계 확인:

```bash
python3 scripts/ask_backend.py docs/collaboration/002-claude-request.md
```

백엔드 구현 요청:

```bash
python3 scripts/ask_backend.py docs/collaboration/002-claude-request.md --mode edit
```

모델과 추론 수준을 지정하지 않으면 사용자의 Codex CLI 설정을 따른다. 명시적으로 선택할 때만 `--model MODEL --effort LEVEL`을 붙인다. 인증은 기존 CLI 설정을 이용하며 별도 API 키나 다른 모델로 자동 전환하지 않는다. 실제 호출은 Codex 사용량을 소모한다.

한 요청은 최대 15분이다. 필요하면 `--timeout`으로 10~3600초를 지정한다. 실행 중에는 Claude의 Bash 도구가 제공하는 백그라운드 실행/완료 알림 또는 대기를 사용한다. 짧은 간격의 반복 상태 확인이나 별도 폴링 루프를 만들지 않는다.

## 2. 결과 읽기

- 터미널 JSON의 `status`가 `completed`인지 확인한다. 실패는 종료 코드 1이다.
- `response`의 Markdown 파일에 답변, 변경 설명, 모델이 수행한 검증 결과가 있다.
- 코드 수정이 있으면 `patch`에 패치 경로, `files`에 변경 파일이 나온다.
- 작업은 현재 HEAD의 별도 worktree에서 수행된다. 공유 폴더의 커밋하지 않은 변경은 자동으로 포함되지 않는다. 필요한 백엔드 변경은 먼저 정리/커밋하고 요청한다. 프런트의 필요한 최신 자료는 요청에 설명한다.
- 모델이 테스트 불가·실패·추가 질문을 보고하면 완료로 간주하지 말고 내용을 확인한다. 실행 도구의 `completed`는 실행과 결과 수집 완료이지 제품 요구사항에 대한 독립적인 합격 판정이 아니다.

## 3. Claude가 공유 작업 폴더에 적용

질문만 했다면 답변을 사용해 UI 작업을 계속한다. 패치가 있다면 응답의 변경 파일을 검토하고, 해당 백엔드 파일에 다른 미완료 변경이 없는지 확인한다. JSON에서 반환된 **실제 경로**를 아래의 `PATCH_PATH`에 넣는다.

```bash
git apply --stat PATCH_PATH
git apply --check PATCH_PATH
git apply PATCH_PATH
```

확인 실패 시 강제 적용하지 말고 최신 코드를 기준으로 후속 요청한다. 적용 후 응답에 명시된 관련 테스트와 프런트 연동을 확인한다. 백엔드 파일만 명시해 별도 커밋한다. `git add .`는 사용하지 않는다. 이미 프런트 파일이 stage되어 있다면 그 변경을 섞지 않도록 `git commit --only -- 백엔드파일들`을 사용하거나 프런트 커밋을 먼저 완료한다. Codex는 이 통합 과정 동안 같은 공유 파일을 따로 수정하지 않는다.

## 실행 범위와 실패 처리

- 기본 `ask`: read-only. `edit`: workspace-write. 대화형 승인은 요청하지 않으며 제한 때문에 못 한 검증은 실패/미검증으로 보고한다. sandbox 우회 옵션은 사용하지 않는다.
- 반환할 패치는 `coach/`, `server.py`, `requirements.txt`, `restore.py`, `setup.sh`, `run.sh`, `tests/test_*.py`, `tests/ide-*.py`로 제한한다. 프런트·공유 문서 변경은 응답으로 요청한다.
- 프런트 파일 변경이나 새 심볼릭 링크가 결과에 포함되면 패치를 반환하지 않는다. 운영 서버/실제 DB/녹화는 작업 대상이 아니다.
- 동시에 백엔드 요청은 하나만 실행한다. 중복 호출은 기존 결과를 반환한다. 동일 번호의 요청 내용/모델/모드 변경은 거부하므로 새 번호를 쓴다.
- 실패 원인을 확인한 뒤 같은 요청을 재시도할 때만 `--retry`를 사용한다. 자동 무한 재시도·다른 에이전트 재호출은 하지 않는다.
- 응답은 `docs/collaboration/`에, 상세 실행 로그와 패치는 Git 내부 `cote-backend-bridge/`에 저장한다. worktree는 실행 종료 시 제거한다.

이 도구가 호출하는 Codex는 사용자가 보고 있는 기존 대화와 별도 실행이다. 협업 문서와 요청 내용을 전달하며, 기존 대화의 전체 기억이나 진행 상태가 자동 공유된다고 가정하지 않는다.
